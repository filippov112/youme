# Project Studio

**Project Studio** — десктопное приложение для управления контекстом при работе с большими языковыми моделями (LLM). Инструмент помогает разработчикам собирать, структурировать и оптимизировать промпты для нейросетей: выбирать нужные файлы проекта, применять шаблоны компоновки, отслеживать количество токенов и формировать готовый контекст для запроса.

---

## 📖 О проекте

При работе с нейросетями (ChatGPT, Claude, Gemini и др.) часто требуется передать модели содержимое нескольких файлов проекта. Вручную собирать такой контекст — долго и неудобно. **Project Studio** решает эту задачу:

- Позволяет **выбрать файлы** через удобное дерево проекта.
- **Формирует контекст** по настраиваемому шаблону (структура промпта задаётся пользователем).
- **Считает токены** для контроля размера запроса.
- **Автоматически копирует** готовый промпт в буфер обмена.
- Поддерживает **выборки файлов** и **компоновки** для типовых сценариев.
- Умеет **объединять JSON-структуры** для работы с описаниями и каталогами.

## ✨ Возможности

### 🌳 Проводник проекта
- Древовидная структура каталогов и файлов с иконками и поддержкой Drag & Drop.
- Создание, удаление, переименование файлов и папок через контекстное меню.
- Автоматическое отслеживание изменений файловой системы (FileSystemWatcher с debounce).
- Сохранение состояния дерева (раскрытые папки, выбранные файлы) между перезагрузками.

### 📝 Редактор
- Встроенный редактор на базе **AvalonEdit** с подсветкой синтаксиса (C#, XML, JavaScript, HTML, CSS, Python, Markdown, JSON).
- Открытие файлов по клику в проводнике.

### 🧩 Компоновки (Layouts)
- Шаблоны структуры промпта с плейсхолдерами (`##context##`, `##query##`, `##path##`, `##content##`).
- **Глобальные** компоновки (для всех проектов) и **проектные** (локальные).
- Выбор активной компоновки в главном окне.

### 📦 Файловые компоненты
- Возможность подключать внешние файлы (например, общие инструкции) к промпту через ключи замены.
- Хранение компонентов в `.prjs/components.json`.

### 🗂 Выборки (Selections)
- Сохранение типовых наборов файлов для быстрого выбора.
- Визуальная индикация отсутствующих файлов.
- Синхронизация с деревом проекта через чекбоксы.

### 🧮 Подсчёт токенов
- Оценка количества токенов через **SharpToken** (`cl100k_base`).
- Отображение в реальном времени при сборке промпта.

### 📚 Работа с документацией
- Копирование каталога-шаблона документации в проект.
- Генерация JSON-структуры каталога для описания проекта.

### ⚙️ Гибкие настройки
- **Глобальная** и **проектная** конфигурация с возможностью переопределения.
- Настройка ключей замены, структуры файла, каталога-шаблона документации.
- Сброс к заводским настройкам.

### 🕒 Последние проекты
- Список недавно открытых проектов с быстрым доступом.
- Хранение в `%LocalAppData%\Schiza\recent_projects.json`.

## 🏗 Архитектура

Проект построен по принципам **Clean Architecture** с разделением на слои:

```
ProjectStudio.sln
├── src/
│   ├── Core/          — доменные модели, интерфейсы, сервисы (независимый слой)
│   ├── Inf/           — инфраструктура: файловая система, настройки, парсинг, работа с ОС
│   └── View/          — WPF-представление (MVVM)
```

### Слои и зависимости

- **Core** — не зависит ни от чего, содержит контракты и бизнес-логику.
- **Inf** — реализует интерфейсы Core (файловая система, конфигурация, каталоги, компоновки).
- **View** — WPF-приложение на MVVM, использует DI-контейнер.

### Ключевые паттерны

- **MVVM** — разделение View и логики через ViewModel'и.
- **MediatR** — публикация событий (например, `CatalogChangedNotification` при изменении файловой системы).
- **Dependency Injection** — `Microsoft.Extensions.DependencyInjection`.
- **Async/Await** — асинхронная работа с файловой системой.
- **DTO ↔ Model** — разделение моделей хранения и передачи.

### Структура Core

| Пространство имён | Назначение |
|---|---|
| `Core.CatalogParser` | Парсинг каталогов в JSON и объединение структур |
| `Core.DocsManager` | Управление документацией проекта |
| `Core.Explorer` | Проводник, файловая система, наблюдение за изменениями |
| `Core.Layouts` | Компоновки и файловые компоненты |
| `Core.PromptBuilder` | Сборка промпта из блоков (Composite-подход) |
| `Core.RecentProjects` | Список недавних проектов |
| `Core.Selections` | Выборки файлов |
| `Core.Settings` | Конфигурация (глобальная/локальная) |
| `Core.Tools` | Утилиты (буфер обмена, счётчик токенов) |

- **.NET 10** (WPF)
- **C# 13** (primary constructors, collection expressions, file-scoped namespaces)

- **Microsoft.Extensions.DependencyInjection** — DI-контейнер
- **Microsoft.Extensions.Logging** — логирование

## 📂 Формат хранения данных

### Глобальная конфигурация
`%AppData%\ProjectStudio\config.json`

### Проектные данные
Хранятся в подпапке `.prjs` в корне проекта:

| Файл | Назначение |
|---|---|
| `.prjs/config.json` | Локальная конфигурация проекта |
| `.prjs/selections.json` | Выборки файлов |
| `.prjs/layouts.json` | Проектные компоновки |
| `.prjs/components.json` | Файловые компоненты |

### Последние проекты
`%LocalAppData%\Schiza\recent_projects.json`

## 🔧 Сборка и запуск

### Требования
- [.NET 10 SDK](https://dotnet.microsoft.com/download)
- Windows 10/11
- Visual Studio 2022+ (или Rider)

### Сборка
```bash
git clone https://github.com/<ваш-логин>/ProjectStudio.git
cd ProjectStudio
dotnet build
```

### Запуск
```bash
dotnet run --project src/View/View.csproj
```

## 🧠 Как это работает

1. **Откройте проект** через меню «Открыть проект» или из списка последних.
2. **Выберите файлы** в дереве проводника (чекбоксы).
3. **Настройте компоновку** в окне «Компоновки сборки» (глобальные или проектные).
4. **Введите запрос** в текстовое поле внизу.
5. Нажмите **«Контекст»** — приложение соберёт промпт по шаблону, подставит содержимое выбранных файлов, посчитает токены и **скопирует результат в буфер обмена**.
6. Вставьте промпт в чат с нейросетью.

### Кнопка «Структура»
Формирует JSON-описание выбранных файлов (без содержимого) — удобно для запросов вида «опиши проект» или «предложи рефакторинг».
